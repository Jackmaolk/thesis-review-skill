# 论文批注要点清单（整合版 v2）

生成时间：2026-10-27　适用：示例大学 2026 版毕业设计（论文）

---

## 一、语气与人设（最高优先级）

### 我的批注长什么样（实测 5 篇历史批注）

| 特征 | 表现 |
|---|---|
| 长度 | 平均 27 字，最长不超过 60 字 |
| 句式 | 命令式：「全改」「重写」「按最新要求改」 |
| 依据 | 「看群里要求」「参考论文看看」「按新格式」 |
| 量词 | 「太少了」「太碎」「太糊」「一大段到底」 |
| 追问 | 「密码用什么算法加密的，写明白」 |
| 不写 | 不解释为什么、不写「建议作者」、不写「该处……」 |

### 必须祛除的 AI 味

**禁止出现：**
- 「41个里37个没问题」这种统计式表述 → 一眼 AI
- 「建议作者」「该处」「综上所述」「值得注意的是」
- 每条批注长度雷同（AI 特征：都是 40 字左右）
- 一条批注讲三件事
- 抽象评价：「逻辑不清」「论证不足」

**正确做法：**
- 一条批注只打一个点，字数有长有短
- 直接说「改什么」「改成什么样」
- 可以用「同上」「都一样」「这个我上次就说了」
- 允许不给理由

## 二、批注数量与分布

- **总量：30 条左右，多几条也行，不超过 35**
- **同一位置最多 1 条**，相关问题合并
- **每个章节都要有批注**（不能只集中在某几章）
- 目录的所有问题合并成 1 条，用换行分点，条理清晰

## 三、格式检查项（按优先级）

### 3.1 页码（新要求）

| 位置 | 页码 |
|---|---|
| 摘要 | **I（罗马数字大写）** |
| 目录 | 接着摘要顺延（II、III…） |
| 正文第1章 | **1（阿拉伯，重新开始）** |
| 正文之后 | 1、2、3… 顺延到结束 |

检查方法：看 `sectPr` 里的 `pgNumType`，摘要节必须是 `upperRoman`，正文第一节必须是 `start=1`。

### 3.2 摘要下边要空一行（新要求）

- 摘要标题（黑体小三）之后，正文开始前**要有一个空行**
- 关键词之后也要空行
- 没有空行 → 批注

### 3.3 每章单独起一页（新要求）

- 每个大章节都必须 `pageBreakBefore` 或前有分页符
- 检查：不能和上一章内容挤在同一页

### 3.4 图表顺序（我之前判错了两次，注意）

**合格标准（宽松）：**

```
（1）声明编号        ← 有更好，没有也行
   ↓
小标题（5.2.3 xxx）  ← 有也算说明
   ↓
文字叙述该图说明什么
   ↓
引用：如图5.8所示 / 如5.8.所示（漏「图」字也算）
   ↓
图题注（宋体五号居中，在图下方）
   ↓
图本身
```

**真正要批的只有：**
- 题注跑到图**上方**的
- 正文**一次都没提过**这个图的
- 图号写法混乱（图4.6 / 图 4.7 / 图4.10 空格不一致）
- 图糊到打印看不清的

**不要批：**
- 没有（1）声明（全篇都没有的话，不算大问题）
- 引用漏了「图」字
- 第三章那种「小标题+叙述+如5.8所示+题注」——这是对的

### 3.5 三线表（注意：边框在单元格层）

- 判断方法：看 `w:tcBorders`，**不是** `w:tblBorders`
- 合格：上线 12（1.5磅）、下线 4、无竖线
- 很多文档表级是 `none`，但单元格层有三线表，**不要误判**

### 3.6 目录

- 标题：黑体小三，不加粗，居中，段前 40 磅段后 20 磅
- 一级：黑体小四；二三级：宋体小四
- 行距固定 20 磅
- 首条可能继承 heading1 而不是 toc1，字体不一致
- 三级目录太多（38 条）可以考虑只到二级

### 3.7 字体字号（2026 版）

| 层级 | 字体 | 字号 |
|---|---|---|
| 章标题 | 黑体 | 小三 (15pt) |
| 二级标题 | 黑体 | 四号 (14pt) |
| 三级标题 | 黑体 | 小四 (12pt) |
| 正文 | 宋体 | 小四 (12pt) |
| 图题注 | 宋体 | 五号 (10.5pt) |
| 表题注 | 黑体 | 五号 (10.5pt) |
| 参考文献 | 宋体 | 五号 (10.5pt) |

英文一律 Times New Roman。

## 四、内容检查项

### 4.1 第一章（重点）

- **每个小标题下的内容太少 → 批注「多写点」**
- **第一章开始就要有 [1][2] 参考文献标注**（实测：这篇一个都没有）
- 结构：研究背景 → 研究现状 → 研究内容 → 论文结构

### 4.2 文献综述

- 整节没有引文献 → 必批
- 只有判断句没有具体研究 → 必批
- 国外部分没有平台名/文献 → 必批

### 4.3 系统设计

- E-R 图要拆分，先叙述再画图
- 详细设计要到类图/接口层级，不能一段话
- 表数量太多要挑核心的放正文，其余进附录

### 4.4 系统实现（最容易水的一章）

- 只有截图没有叙述 → 必批
- 每个功能要讲：怎么实现、用了什么技术、难点在哪

### 4.5 系统测试（问题最大，要专业指导）

**这一章要重点批，专业度要够：**

| 检查点 | 说明 |
|---|---|
| 用例数量 | 三端系统 20 条以下就是不够 |
| 异常用例 | 必须有：重复预订、超售、非法日期、越权 |
| 通过率 | 全部「符合预期」不合常理，要有缺陷记录表 |
| 测试环境 | 服务器配置、数据库版本、浏览器版本 |
| 压测工具 | JMeter / LoadRunner，说清并发数、持续时间 |
| 性能指标 | 单次测量不算性能测试，至少 3 次取平均 |
| 数据采集 | CPU/内存是峰值还是均值，什么时刻采的 |
| 结论 | 「7×24 连续运行」没测过就别写 |
| 安全测试 | 密码算法要写清（BCrypt/MD5、是否加盐） |

### 4.6 结论

- 太少 → 批注要多写
- 要写：做出什么、遇到什么问题怎么解决、还有什么没做好、后面怎么提升
- 「可以正式投入使用」这类话要说小

### 4.7 参考文献

- 年份越界（2026年第3期，5月定稿时还没出版）
- 引错文献（比如引了 Program VUE 的晶体学论文）
- 格式不完整（缺卷期）
- 知网收录的纸质期刊不能标 [J/OL]
