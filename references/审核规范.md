# 论文审核批注规范（整合版）

来源：TashanGKD/tashan-research-skills（19★）的 `thesis-audit-reviewer` +
ZyhSechub/chinese-thesis-workbench-skill（588★）的 `ai-review-rubric.json` +
本机教师历史批注（Teacher，5 篇样本）

## 一、批注语气：两种模式

### 模式 A：教师口语（默认，用于给学生）

本机历史批注统计，平均 27 字/条：

- 命令式为主：「全改」「重写」「按最新要求改」「不留」
- 指出依据：「看群里要求」「参考论文看看」「按最新格式」
- 不解释理由，默认学生会懂
- 常用量词：「太少了」「太碎」「太糊」「一大段到底」
- 追问式：「密码用什么算法加密的，写明白」

### 模式 B：审核书面语（用于正式评审意见/存档）

来自 tashan 的 comment_language.md：

- 该处……／应补充……／建议作者……／不宜将……
- 每条必须给定位，不给泛泛的「逻辑不清」
- 确定性分级：确认问题／疑似问题／需作者补充材料／无法判断

**注意：模式 B 的「建议作者」很啰嗦，给学生的批注一律用模式 A。**

## 二、问题分类（tashan A–K）

| 类 | 覆盖 |
|---|---|
| A 摘要与关键词 | 摘要结构、中英一致、结论强于证据 |
| B 结构与编号 | 目录、章节号、图号表号公式号、跨页续表 |
| C 研究问题与框架 | 概念界定、目标一致、章节递进 |
| D 文献综述 | 只罗列不述评、缺近年文献、来源不规范 |
| E 研究设计 | 样本、编码、审计轨迹 |
| F 模型数据 | 公式编号、变量解释、数据口径、表格内部逻辑 |
| G 结果与结论 | 外推过度、强词、小结不回应问题 |
| H 政策建议 | 建议非由结果推导 |
| I 外部事实与引用 | 无来源、未核验、重复文献、年份越界 |
| J 内部一致性 | 同一数字前后不一致、交叉引用指向错误 |
| K 覆盖与交付 | 声称逐行审阅但无覆盖矩阵 |

## 三、Word 批注必须守的（tashan docx_integrity_gate.md）

禁止：
- 把工具输出预览当成全文阅读
- 只读目录和表格就声称逐行审阅
- 未看公式渲染就判断公式完整
- 把抽取失败导致的公式空白判为作者错误
- 把「对象已登记」等同于「对象已检查」

DOCX 状态口径：visible / needs_render_check / needs_ooxml_check / blocked

## 四、本机 DOCX 结构体检（实测Student论文）

```
段落 1213 / 表格 19 / 图片 32 / 媒体文件 33（含 2 个 EMF）
公式 0 / 脚注 0 / 尾注 0 / 修订 0
域代码 513 / 书签 205 / 批注 26
risk_flags:
  visual_objects_require_render_check
  comments_or_revisions_require_ooxml_or_word_check
  field_codes_cross_references_or_toc_require_check
```

域代码 513 个、书签 205 个 —— 说明目录、页码、交叉引用都是域，**不能用 python-docx 文本抽取判断**。

## 五、踩过的坑

1. **三线表误判**：Word 常把边框设在单元格（`w:tcBorders`）而非表格（`w:tblBorders`）。
   只看 tblBorders 会得出「没有三线表」的错误结论。实测 19 张表中 18 张是合格三线表
   （上线 12/1.5磅、下线 4、无竖线）。
2. **目录首条样式**：目录第一条可能继承 heading 1 而非 toc 1，字体因此不一致。
3. **PowerShell 中文弯引号**：`""` 会被当作字符串定界符，必须用 base64 传参。
4. **`\f` 转义**：路径里 `\final_` 会被解析成换页符，导致 Save 失败。

## 六、批注密度控制

- 全文 20–30 条，不超过 30
- 同一位置最多 1 条，相关问题合并
- 优先级：致命问题（文献造假、结论无据）> 结构问题 > 格式问题
