# 论文批注生成规则 v3（可执行版）

最后更新：2026-10-27
依据：示例大学 2026 版格式规范 + 本机 16 篇历史批注（190 条）+ 教师口头确认

---

## 0. 三条铁律

1. **以论文规范为准，不以我的旧批注为准**。规范说表题黑体 11pt，就是黑体 11pt。
2. **批注像人说话**：短、直、命令式。禁止统计腔（「41个里37个没问题」）。
3. **同一位置只批一条**，相关问题合并；全文 30–35 条。

---

## 1. 语气规则

### 1.1 允许的句式

| 类型 | 示例 |
|---|---|
| 全盘否定 | 格式全错，按最新要求改 |
| 命令 | 重写、全改、都改了、删掉 |
| 判断 | 太少了、太碎了、太糊了、一大段到底 |
| 追问 | 密码用什么算法加密的，写明白 |
| 极简 | 改 / 同上 / 图呢 / 断表 / 单独一页 |
| 引用规范 | 黑体小三号，段前40pt段后20pt，行距20pt |

### 1.2 禁止的词

```
建议作者／该处／综上所述／值得注意的是／整体较好／占比／X个里Y个
```

### 1.3 长度控制

- 平均 25–30 字
- 允许 2 字（「改」）到 60 字
- 禁止每条都是 40 字左右，那是最明显的 AI 特征

---

## 2. 结构检查

### 2.1 章节分页

- 每个大章节单独起页（pageBreakBefore 或前面有分页符）
- 批注：`每个大章节都是单独一页`

### 2.2 页码

| 位置 | 页码 | 检查点 |
|---|---|---|
| 摘要 | I（upperRoman） | pgNumType fmt="upperRoman" |
| 目录 | 顺延 II、III | 不能重新 start |
| 正文 | 1（阿拉伯，重新开始） | 正文首节 pgNumType start=1 |

### 2.3 页眉

- 正文之前（封面、声明、摘要、目录）不能有页眉
- 正文开始才有「示例大学毕业设计」
- 批注：`正文以前都没有页眉，去掉示例大学学士论文`

### 2.4 摘要

#### 字数（硬指标）

| 字数 | 处理 |
|---|---|
| 少于 400 | 批注：`摘要太少，四百字以上` |
| 400–500 | 合格，不批 |
| 超过 500 | 批注：`摘要太多，五百字左右` |

#### 空格

- 摘要标题后要空一行才开始正文
- 关键词之后也要空行
- 批注：`空一行就行，往上去一行`

---

## 3. 参考文献标注（重点）

### 3.1 格式

- Times New Roman，小四（12pt），上标
- 从第 1 章开始就要出现，一直到第 6 章
- 按 [1][2]...[15] 顺序，与文末对应

### 3.2 检查方法

逐章统计 [n] 独立 run 数量：

```
第1章: 4 处  OK
第2章: 11 处 OK
第3章: 0 处  -> 要批
第4章: 0 处  -> 要批
第5章: 0 处  -> 要批
第6章: 0 处  -> 要批
```

### 3.3 批注话术

- 全篇都没有：`论文从第一章开始到最后几章要引入使用参考文献的标志[1][2]...[15]，按顺序正确引入`
- 前面有后面没有：`第三章往后一个文献标注都没有了，补齐`
- 数量不够：`要到15个文献` / `找点英文参考文献`

## 4. 图表规则

### 4.1 顺序（宽松判定）

```
（1）声明编号     <- 仅【小的 E-R 图 / 功能子图】需要
   |
小标题 + 文字叙述
   |
引用：如图5.8所示（漏「图」字也算）
   |
图题注
   |
图本身
```

（1）（2）编号的适用范围：

| 场景 | 要不要（1） |
|---|---|
| E-R 图拆分成多个小图 | 要，每个小图前标（1）（2）（3） |
| 功能模块子图 | 要 |
| 第五章整页系统截图 | 不需要 |
| 表格 | 按章编号（表4.1），不用（1） |

合格判据（任满足一项即过）：

- 有（n）声明
- 有小标题 + 叙述
- 正文有引用（如图4.1所示，或 如4.1.所示）

真需要批的只有：

- 题注跑到图上方
- 正文一次都没提这个图
- 图号写法混乱（图4.6 / 图 4.7 / 图4-1）
- 图糊到打印看不清

### 4.2 图题注格式（以规范为准）

```
黑体 11pt，居中，置于图下方
段前 6 磅，段后 12pt，单倍行距
图序与图名之间空一个汉字符
```

注意：不是宋体五号。前期判错过，以规范原文为准。

### 4.3 图的大小与拆分

- 图太小看不清 -> 批注：`拆分，图太小看不清`
- 大图含多个模块 -> 批注：`按功能模块拆成单独的小图，表上序号（1）（2）以此类推`
- 这是最高频问题之一（16 篇里 8 篇都有）

### 4.4 表格格式（以规范为准）

```
三线表：上下粗线 1.5pt、表头下细线 1pt、无竖线
表题：黑体 11pt，居中，在表上方
表序与表名之间空一个汉字符
```

判断方法：看 w:tcBorders（单元格层），不是 w:tblBorders。

### 4.5 表格断开

- 表跨页 -> 断开处要写「续表 4.7」并重复表头
- 批注：`表格不要断开` / `断开的写续表4.7，尽量别断开`

### 4.6 表格数量

- 正文留 10 张左右核心表，其余进附录
- 批注：`表格太多，留十个就行了`
- 测试章：`测试不用太多，五六个表就行`

## 5. 各章内容规则

### 5.1 第一章

结构必须四块：1.1 研究背景 / 1.2 国内外研究现状 / 1.3 研究内容 / 1.4 论文结构

- 缺块 -> `第一章重新写，按照文献的结构：研究现状、研究内容、结构。第一章内容太少了`
- 小标题下内容太少 -> 单独批
- 必须开始出现 [n] 标注

### 5.2 第二章

- 要有导航小标题（每项技术一个）
- 技术名称要具体
- 批注：`第二章没有导航小标题，改一下` / `重写具体的技术名称，参考论文`

### 5.3 第三章

- 要加需求分析图
- 批注：`加几个需求分析图`

### 5.4 第四章（E-R 图重灾区）

- E-R 图必须拆分，先叙述再画图
- 批注：`重新画，拆分小的图，e-r图怎么画的，要拆分先叙述在画图`

### 5.5 第五章（最容易水）

- 不能只贴截图
- 每个功能：先叙述实现 -> 再放图
- 批注：`第五章重写，要先叙述文字介绍，在放图片`
- 没有叙述只有图 -> `内容太少，要写实现的功能模块`

### 5.6 第六章测试（重点批）

| 项 | 标准 | 批注话术 |
|---|---|---|
| 测试方法 | 必须写明黑盒/白盒 | `测试方法要写上具体的黑盒白盒测试，测试案例` |
| 用例表 | 必须有，五六个表 | `要写测试用例！` |
| 表数量 | 5–6 个 | `测试不用太多，五六个表就行` |
| 覆盖率 | 每个功能至少一条 | `22条用例对17个功能，覆盖不够` |
| 异常用例 | 重复、超售、越权、非法输入 | `要有异常用例` |
| 全部通过 | 不合常理，要有缺陷表 | `全部符合预期不正常，补缺陷记录表` |
| 测试环境 | 服务器、DB版本、浏览器 | `测试环境写清楚` |
| 压测 | 工具、并发数、持续时间 | `什么压测工具、什么服务器配置` |
| 性能数据 | 至少 3 次取平均 | `单次测量不算性能测试` |

### 5.7 结论

- 太少 -> 批
- 内容要写：做出什么 -> 遇到什么问题 -> 怎么解决 -> 有哪些成绩 -> 后面怎么提升
- 批注：`结论太少了，多写点：出现什么问题，怎么解决的，最后在怎么提升`
- 吹过头 -> `这话说大了，改成具备投入试运行条件就行`

### 5.8 参考文献

- 少于 15 个 -> `要到15个文献`
- 全中文 -> `找点英文参考文献`
- 年份越界 -> 批
- 引错文献 -> 批
- 格式缺卷期 -> 批

## 6. 格式检查项

### 6.1 字体字号（2026 版）

| 位置 | 字体 | 字号 |
|---|---|---|
| 章标题 | 黑体 | 小三 15pt |
| 二级标题 | 黑体 | 四号 14pt |
| 三级标题 | 黑体 | 13pt |
| 正文 | 宋体 | 小四 12pt |
| 图题注 | 黑体 | 11pt |
| 表题注 | 黑体 | 11pt |
| 参考文献 | 宋体 | 五号 10.5pt |

英文一律 Times New Roman。

### 6.2 目录

```
标题：黑体小三，不加粗，居中，段前40pt 段后20pt 行距20pt
「目录」两字之间空两个汉字符宽度
一级：黑体小四，行距20pt，行前空6pt 行后空0pt
其他级：宋体小四，行距20pt，下级比上级左空两个汉字符
必须自动生成
```

目录全部问题合并成 1 条，换行分点。

### 6.3 不加粗

标题容易误加粗 -> `不加粗` / `检查所有的都不加粗`

---

## 7. 批注分布要求

- 每个章节都要有批注
- 全篇 30–35 条
- 同一位置最多 1 条
- 目录合并成 1 条
- 测试章可以多几条
